# HOME:ET 산출식 명세 (v2)

자취지수(①)와 적정 월세 상한(②)의 계산 방식, 상수, 코드 위치를 정리한 문서입니다.
모든 금액은 원, 모든 값은 **방학 포함 월평균**입니다. 경로는 레포 루트 기준입니다.

> **v2 변경 요지**: 가중치 민감도 완화(γ 완충), 슬라이더 범위 축소, LLM 가중치 추출을 −2~+2 등급 방식으로 변경. 시간·비용 계산(3-1 ~ 3-3)은 v1과 같습니다. 자세한 차이는 [7. v1과 다른 점](#7-v1과-다른-점)에 있습니다.

## 3. 계산 순서 (`compute()`, `lib/calc.ts:74`)

### 3-1. 되찾는 시간 (v1과 같음)

```
commuteDailyMin    = 2·T₁ + h                         // lib/calc.ts:81
savedDailyMin      = max(0, commuteDailyMin − L)      // :82
D                  = d × 32/12                        // :83  월 등교일
ΔH                 = savedDailyMin / 60 × D           // :84  월 절약 시간
```

### 3-2. 시간·체력의 금액 가치 (v1과 같음)

```
G_time       = ΔH × w                                 // :86
f            = min(0.5, 0.15 + 0.1·n)                 // :46  fatigueCoef()
fatigueHours = ΔH × f
G_body       = fatigueHours × w                       // :89
```

### 3-3. 자취 추가 비용 (v1과 같음)

```
initialMonthly = I / 24                               // :91
depositCost    = Dp × r / 12                          // :92
savedFare      = max(0, F − F_L) × D                  // :93
ΔC = R + M + Lv + initialMonthly + depositCost − savedFare   // :94
```

### 3-4. 가중치 반영과 자취지수 (**v2 변경**)

가중치를 그대로 곱하지 않고, 균등(1/3)을 1로 두는 배율에 γ 제곱을 씌워 완충합니다.

```
a(x) = (3x)^γ              // γ = GAMMA = 0.5, lib/calc.ts:36

E = G_time·a(w_t) + G_body·a(w_b)     // :98  가치관 반영 이득
K = ΔC·a(w_m)                          // :99  가치관 반영 비용

index = 100            if ΔC ≤ 0      // :102
        0              if E + K ≤ 0   // :103
        100·E / (E+K)  otherwise      // :104
```

```ts
const amp = (x: number) => Math.pow(3 * x, GAMMA);
const E = timeValue * amp(w.time) + bodyValue * amp(w.body);
const K = extraCost * amp(w.money);
```

**성질**
- 균등 가중치이면 `a = 1`이라 가중치 없이 비교한 것과 같습니다(v1과 동일).
- γ = 1이면 v1 식과 같고, γ = 0이면 가치관을 무시합니다.
- 가중치 범위가 [0.15, 0.60]이므로 배율 `a`는 약 0.67 ~ 1.34 안에서만 움직입니다. v1은 0.39 ~ 1.64였고, 돈 가중치가 분모로 들어가는 지불 의향은 최대 7배까지 차이가 났습니다.

**판정**: `index ≥ 50`이면 "자취 추천", 미만이면 "다시 생각해 보기". 50 단일 기준입니다. (45~55 "애매함" 구간 추가 여부는 팀 확정 필요)

### 3-5. 지불 의향과 1시간 비교

```
W            = E / a(w_m)        // :107  w_m ≥ 0.15 이므로 화면에선 항상 유한
myHourValue  = W / ΔH            (ΔH = 0 이면 0)      // :128  "내가 매기는 1시간의 가치"
buyBackPrice = ΔC / ΔH           (ΔH = 0 이면 0)      // :129  "자취로 1시간을 되사는 가격"
```

`index ≥ 50 ⇔ E ≥ K ⇔ W ≥ ΔC ⇔ myHourValue ≥ buyBackPrice` 이므로 리포트의 두 막대 비교는 판정과 항상 일치합니다.

### 3-6. 적정 월세 상한 (②)

`index = 50`, 즉 `W = ΔC`가 되는 `R`을 역산합니다(식은 v1과 같고 `W`만 3-5의 새 값).

```
rentCap = W − M − Lv − initialMonthly − depositCost + savedFare   // lib/calc.ts:108
```

화면 표시는 `max(0, rentCap)`입니다. `w_m`이 0이 될 수 없으므로 v1의 "제한 없음" 분기는 화면에서 삭제했습니다. (`compute()`를 `w_m = 0`으로 직접 부르면 `W = +∞`가 그대로 나옵니다.)

**② 화면에서의 호출** (`lib/view-models.ts:102`):

```ts
compute(state.commute, { ...state.costs, rent: region.rentMedian, mgmt: region.mgmtMedian },
        weights, region.oneWayMin * 2, regionFare(region))
```

- `L = 지역→학교 편도 × 2`. 자취 쪽에는 배차 대기 시간을 넣지 않습니다.
- `F_L = regionFare(region)`, `M`은 선택 지역의 관리비 중앙값입니다.
- **`R`은 상한식에 들어가지 않습니다.** 지역 월세 중앙값은 비교 문구에만 쓰입니다.

**비교 문구** (`rentMessage`, `lib/view-models.ts:79`):

| 조건 | 문구 요지 |
| --- | --- |
| `rentCap ≤ 0` | 어떤 월세를 내도 통학보다 손해 |
| `rentCap ≥ 중앙값 × 1.5` | 시세 안에서 넓게 고를 수 있음 |
| `rentCap ≥ 중앙값` | 중앙값이 상한 안에 들어옴 |
| 그 외 | 중앙값이 상한보다 높음, 더 싼 방이나 다른 지역 비교 권장 |

① 리포트 화면은 `compute(state.commute, state.costs, weights)`로 호출합니다(`lib/view-models.ts:25`). `L = 20`, `F_L = 0` 기본값을 씁니다.

## 4. 가중치 (**v2 변경**)

### 4-1. LLM 등급 추출 (`app/api/weights/route.ts`)

LLM은 퍼센트가 아니라 **축별 −2 ~ +2 정수 등급**만 뽑고, 가중치 변환은 코드가 합니다. 같은 문장에서 결과가 덜 흔들리게 하기 위해서입니다.

- 모델: `GEMINI_MODEL` 환경 변수, 기본 `gemini-3.8-flash` (**실제로 제공되는 모델명인지 확인 필요**)
- 시스템 지시: `:11`, few-shot: `:27`, JSON 스키마: `:70`, zod: `:93`, 호출: `:126`
- 호출 설정: `responseMimeType: application/json` + `responseJsonSchema`, `temperature: 0`, `abortSignal`로 15초 타임아웃 (시간이 지나면 요청 자체를 끊음)
- 요청 본문: `{ "goal": "고른 칩 문장 + 추가 설명" }` (최대 1,000자). JSON이 아니면 400

**LLM 출력 스키마**

```json
{
  "money": -2, "time": 0, "body": 2,
  "evidence": [{ "quote": "원문 일부", "axis": "money", "dir": "+" }],
  "confidence": "high" | "medium" | "low"
}
```

**등급 의미**: 0 = 평균적인 대학생 수준, +1/+2 = 더 중요하게 여김, −1/−2 = 덜 중요하게 여김.

**프롬프트 규칙**
1. 문장에서 언급이 없는 축은 0으로 둔다.
2. `evidence.quote`는 원문에 있는 표현을 그대로 옮긴다.
3. 부정 표현은 음수로 처리한다. 예: "돈은 부모님이 지원해 주셔서 괜찮아요" → money −1
4. 한 표현이 두 축에 걸릴 수 있다. 예: "동아리를 못 해서 아쉬워요" → time +1, body +1

**Few-shot 예시 구성 (6개)**

| # | 유형 | 예시 입력 | 출력 (money / time / body) |
| --- | --- | --- | --- |
| 1 | 돈 중심 | 알바해서 월세 내야 해서 돈이 제일 걱정이에요 | +2 / 0 / 0 |
| 2 | 시간 중심 | 공부할 시간이 부족해서 통학 시간이 아까워요 | 0 / +2 / 0 |
| 3 | 체력 중심 | 통학하면 너무 지쳐서 수업에 집중이 안 돼요 | 0 / +1 / +2 |
| 4 | 혼합 | 돈도 아껴야 하는데 아침 1교시가 너무 힘들어요 | +1 / 0 / +1 |
| 5 | 부정 | 돈은 부모님이 지원해 주셔서 괜찮고, 시간이 더 중요해요 | −1 / +1 / 0 |
| 6 | 무관·빈 문장 | 그냥 궁금해서 해봐요 | 0 / 0 / 0 (confidence low) |

> 평가용 테스트 문장(4-4)은 few-shot 예시에 넣지 않습니다.

**서버 후처리**
1. zod로 스키마 검증 (등급은 −2 ~ 2 정수)
2. `evidence.quote`가 원문에 실제로 포함되는지 문자열 검사(`quoteExists()`, `lib/weights.ts:38`). 없으면 그 근거만 버림: `:141`
3. 4-2로 가중치 변환: `:144`
4. 키가 없거나, 실패하거나, 스키마가 맞지 않으면 4-3 키워드 분석으로 대체

**API 응답** (`WeightAnalysis`, `lib/weights.ts`). LLM이든 대체 분석이든 같은 모양이고, 앱 상태에 그대로 저장합니다.

```json
{
  "money": 0.29, "time": 0.43, "body": 0.28,
  "source": "llm" | "keyword" | "default",
  "levels": { "money": 1, "time": 2, "body": 1 } | null,
  "evidence": [{ "quote": "…", "axis": "time", "dir": "+" }],
  "confidence": "high" | "medium" | "low",
  "reason": "“학점 관리” → 시간↑, …"
}
```

`reason`은 남은 근거로 만든 한 줄이고, 근거가 하나도 남지 않으면 "뚜렷한 근거를 찾지 못했다"는 문구입니다. 대체 분석은 `levels: null`, `evidence: []`, `confidence: "low"`입니다.

### 4-2. 등급 → 가중치 변환 (`levelsToWeights()`, `lib/weights.ts:27`)

```
raw_k = 1.5^(s_k)                 // s_k ∈ {−2, …, 2}
w_k   = raw_k / Σ raw
→ [0.15, 0.60]으로 자르고, 남거나 모자란 몫은 범위 안의 축에 기존 비율대로 재분배
  (clampWeights(), lib/calc.ts:185. 상한 초과를 먼저 고정하고, 없을 때만 하한 미달을 고정)
→ toPercents()로 정수 % 변환
```

예: money +1, time +2, body +1 → raw 1.5 / 2.25 / 1.5 → **29% / 43% / 28%**

### 4-3. 키워드 대체 분석 (`keywordWeights()`, `lib/weights-keyword.ts`)

```
weight_k ∝ 1 + 2 × (k 키워드 등장 수)       // :26
```

결과는 4-2와 같은 [0.15, 0.60] 범위 처리를 거칩니다. 키워드가 없거나 글이 비어 있으면 균등(1/3)입니다.

### 4-4. 정확도 검증

- 테스트 문장 20~30개에 팀원이 직접 등급을 매기고 LLM 결과와 비교합니다.
- 지표: 축별 등급 일치율, ±1 이내 일치율.

### 4-5. 슬라이더 (`toPercents` `:141`, `rebalance` `:158`, `lib/calc.ts`)

- 정수 %로 관리하고 합은 항상 100입니다. `toPercents`는 money와 time을 반올림하고 body에 나머지를 줍니다.
- 5% 단위로 스냅합니다.
- `rebalance`: 바꾼 값을 5% 단위로 맞추고 **[15, 60]**으로 자른 뒤, 남은 몫을 나머지 둘에 기존 비율대로(5% 단위) 나눕니다. 나머지 둘도 각각 [15, 60] 안입니다. 예: 하나를 15로 내리면 남은 85를 나눌 때 한쪽이 60을 넘지 않게 25 ~ 60으로 제한합니다.
- AI 분석값(예: 29 / 43 / 28)은 5% 단위가 아닐 수 있습니다. "AI 분석값으로" 버튼은 그 값을 그대로 넣고, 슬라이더를 움직이는 순간 세 값 모두 5% 단위로 맞춰집니다.
- v1 저장값(범위 [5, 90], 예전 분석 결과 형태)은 불러올 때 `clampPercents()`(`:169`)로 범위 안에 넣고 새 형태로 바꿉니다(`lib/app-state.ts:119`).
- 화면의 지수·막대는 약 0.3초 ease-out 애니메이션으로 갱신합니다. 지수 숫자는 `useTweened()`(`components/screens/report-screen.tsx`), 막대는 `Meter`의 CSS transition입니다.

이 사용자처럼 추가 비용이 되찾는 가치의 약 2배이면, 슬라이더를 어떻게 움직여도 판정이 뒤집히지 않습니다(22.3 ~ 46.0). 가치관은 결과를 조정하지만 객관적 비용 차이를 뒤집지는 못하게 하는 것이 v2의 의도입니다.

빠른 확인용 스크립트 (Node 22+는 TS를 바로 실행합니다. 단, `lib/*.ts`의 import에 확장자가 없어서 `.ts`를 붙인 복사본이나 tsx 같은 실행기가 필요합니다):

```ts

const c = { oneWayMin: 85, transfers: 2, headwayMin: 15, roundTripFare: 4500, daysPerWeek: 4, hourlyWage: 10320 };
const cost = { rent: 550000, mgmt: 70000, living: 150000, initialTotal: 1650000, deposit: 10000000, annualRate: 0.035 };
compute(c, cost, { money: .29, time: .43, body: .28 }).index;           // 36.57
compute(c, cost, { money: .2, time: .45, body: .35 }, 20, 0).rentCap;   // 324,325
```

## 8. 알려진 한계 / 팀 확정 필요

- **γ 값**: 0.5(극단 조작 시 판정이 바뀔 여지 있음) vs 0.3(가치관만으로는 판정이 거의 안 바뀜) 중 선택.
- **판정 기준**: 50 단일 기준. 45~55 "애매함" 구간 추가 여부.
- **피로 계수**: 환승 횟수만 씁니다. 혼잡 시간대나 도보 시간은 반영하지 않습니다. 계수 자체의 근거 자료가 없습니다.
- **생활비·초기 비용·이율**: 기본값에 근거 자료가 없습니다. 초기 비용 중 중개보수는 법정 요율로 자동 계산할 수 있습니다.
- **빠진 변수**: 자취 시 가사노동 시간, 통학 중 활용 가능한 시간 비율, 청년 월세 지원금. 현재 식은 자취 쪽에 유리하게 편향될 수 있습니다.
- **자취 쪽 통학 시간**: 배차 대기를 넣지 않아서 통학 쪽과 비대칭입니다.
- **`F_L`**: 3,000원 상수입니다. 실제 요금이나 환승 할인을 반영하지 않습니다.
- **통학 정보**: 길찾기 API가 미정이라 사용자가 직접 입력합니다.
- **시세 데이터**: 6개 학교 × 3개 동의 예시 값입니다. 국토부 전월세 실거래가 가공 전입니다.
- **극단값**: ΔH = 0이고 ΔC > 0이면 E = 0이라 지수는 0입니다.
