# HOME:ET 산출식 명세

자취지수(①)와 적정 월세 상한(②)의 계산 방식, 상수, 코드 위치를 정리한 문서입니다.
모든 금액은 원, 모든 값은 **학기 중 한 달** 기준입니다(월 등교일 = 주당 등교일 × 4.3, 방학 미반영). 경로는 레포 루트 기준입니다.

> 계수는 팀 확정 전 초안입니다. 기획서의 초안 식이 아니라 **프로토타입 화면 숫자**에 맞춰 구현했습니다. 차이점은 [기획서 초안과 다른 점](#기획서-초안과-다른-점)에 있습니다.

---

## 1. 입력

| 기호 | 의미 | 필드 (`Commute` / `LivingCosts`) |
| --- | --- | --- |
| `T₁` | 본가→학교 편도 소요시간(분) | `oneWayMin` |
| `n` | 환승 횟수 | `transfers` |
| `h` | 배차 간격(분). 대기 여유 시간으로 하루 1회 반영. **현재는 입력 질문을 없애고 0으로 고정**(Google 경로 시간에 환승 대기가 포함됨) | `headwayMin` |
| `F` | 통학 왕복 교통비 | `roundTripFare` |
| `d` | 주당 등교일 | `daysPerWeek` |
| `w` | 1시간의 기준 시급. **입력 질문을 없애고 2026 최저임금 10,320원으로 고정**. 개인차는 가중치가 반영(`myHourValue = w·(w_t + f·w_b)/w_m`) | `hourlyWage` |
| `R` | 월세 | `rent` |
| `M` | 관리비 | `mgmt` |
| `Lv` | 추가 생활비 | `living` |
| `I` | 초기 비용 총액 (중개수수료·이사·가구가전) | `initialTotal` |
| `Dp` | 보증금 | `deposit` |
| `r` | 보증금 기회비용 연이율 | `annualRate` |
| `L` | 자취 시 하루 왕복 통학(분) | `compute()` 4번째 인자 |
| `F_L` | 자취 시 하루 왕복 교통비 | `compute()` 5번째 인자 |
| `w_m, w_t, w_b` | 돈·시간·체력 가중치 (합 1) | `Weights` |

| 상수 | 값 | 위치 |
| --- | --- | --- |

| `DEFAULT_LIVING_ROUND_TRIP_MIN` | 20분 (①의 학교 주변 자취 가정) | `lib/calc.ts:28` |
| `DEFAULT_COSTS.living` | 150,000 | `lib/calc.ts:31` |
| `DEFAULT_COSTS.initialTotal` | 800,000 (24개월 분할). 예전 기본값 1,650,000이 저장돼 있으면 불러올 때 800,000으로 바꿈 | `lib/calc.ts`, `lib/app-state.ts` |
| `DEFAULT_COSTS.deposit` | 10,000,000 | `lib/calc.ts:31` |
| `DEFAULT_COSTS.annualRate` | 0.035 | `lib/calc.ts:31` |
| `MIN_WAGE_2026` | 10,320 | `lib/calc.ts` |
| `regionFare` | 자취 지역이 도보면 0, 버스·지하철이면 3,000 (왕복) | `lib/app-state.ts:66` |

`R`, `M`의 기본값은 학교별 첫 번째 동의 시세 중앙값입니다(`lib/data.ts`, 예시 데이터).

## 3. 계산 순서 (`compute()`, `lib/calc.ts:67`)

### 3-1. 되찾는 시간

```
commuteDailyMin    = 2·T₁ + h                         // lib/calc.ts:74
savedDailyMin      = max(0, commuteDailyMin − L)      // :75
D                  = d × 4.3                          // 월 등교일
ΔH                 = savedDailyMin / 60 × D           // :77  월 절약 시간
```

### 3-2. 시간·체력의 금액 가치

```
G_time       = ΔH × w                                 // :79
f            = min(0.5, 0.15 + 0.1·n)                 // :39  fatigueCoef()
fatigueHours = ΔH × f
G_body       = fatigueHours × w                       // :82
```

### 3-3. 자취 추가 비용

```
initialMonthly = I / 24                               // :84
depositCost    = Dp × r / 12                          // :85
savedFare      = max(0, F − F_L) × D                  // :86
ΔC = R + M + Lv + initialMonthly + depositCost − savedFare   // :87
```

### 3-4. 가중치 반영과 자취지수

```
E = 3 · (w_t·G_time + w_b·G_body)                     // :90
K = 3 · w_m · ΔC                                      // :91

index = 100            if ΔC ≤ 0                      // :94
        0              if E + K ≤ 0                   // :95
        100·E / (E+K)  otherwise                      // :96
```

- 가중치가 균등(각 1/3)이면 `3w = 1`이라 가중치 없이 비교한 것과 같습니다.
- **판정**: `index ≥ 50`이면 "자취 추천", 미만이면 "다시 생각해 보기". 50 단일 기준입니다.

### 3-5. 지불 의향과 1시간 비교

```
W            = E / (3·w_m)       (w_m = 0 이면 +∞)    // :98
myHourValue  = W / ΔH            (ΔH = 0 이면 0)      // :119  "내가 매기는 1시간의 가치"
buyBackPrice = ΔC / ΔH           (ΔH = 0 이면 0)      // :120  "자취로 1시간을 되사는 가격"
```

`index ≥ 50 ⇔ E ≥ K ⇔ W ≥ ΔC ⇔ myHourValue ≥ buyBackPrice` 이므로 리포트의 두 막대 비교는 판정과 항상 일치합니다.

### 3-6. 적정 월세 상한 (②)

`index = 50`, 즉 `W = ΔC`가 되는 `R`을 역산합니다.

```
rentCap = W − M − Lv − initialMonthly − depositCost + savedFare   // lib/calc.ts:99
```

화면 표시는 `max(0, rentCap)`이고, `W = +∞`이면 "제한 없음"입니다.

**② 화면에서의 호출** (`lib/view-models.ts:103`):

```ts
compute(state.commute, { ...state.costs, rent: region.rentMedian, mgmt: region.mgmtMedian },
        weights, region.oneWayMin * 2, regionFare(region))
```

- `L = 지역→학교 편도 × 2`. 자취 쪽에는 배차 대기 시간을 넣지 않습니다.
- `F_L = regionFare(region)`
- `M`은 선택 지역의 관리비 중앙값입니다.
- **`R`은 상한식에 들어가지 않습니다.** 지역 월세 중앙값은 아래 비교 문구에만 쓰이고, 지역은 `L`, `F_L`, `M`을 통해서만 상한에 영향을 줍니다.

**비교 문구** (`rentMessage`, `lib/view-models.ts:79`):

| 조건 | 문구 요지 |
| --- | --- |
| `W = +∞` | 돈 가중치 0, 상한 없음 |
| `rentCap ≤ 0` | 어떤 월세를 내도 통학보다 손해 |
| `rentCap ≥ 중앙값 × 1.5` | 시세 안에서 넓게 고를 수 있음 |
| `rentCap ≥ 중앙값` | 중앙값이 상한 안에 들어옴 |
| 그 외 | 중앙값이 상한보다 높음, 더 싼 방이나 다른 지역 비교 권장 |

① 리포트 화면은 `compute(state.commute, state.costs, weights)`로 호출합니다(`lib/view-models.ts:25`). `L = 20`, `F_L = 0` 기본값을 쓰고, `R`, `M`은 사용자가 "가정값 직접 고치기"에서 수정할 수 있습니다.

## 4. 가중치

### 4-1. Gemini 추출 (`app/api/weights/route.ts`)

- 모델: `GEMINI_MODEL` 환경 변수, 기본 `gemini-flash-lite-latest` (Flash 계열은 붐빌 때 503이 잦음)
- 프롬프트: `:8`
- JSON 스키마 `{money, time, body, reason}`: `:27`
- 호출: `:54`. `responseMimeType: application/json` + `responseJsonSchema`, 타임아웃 15초
- zod로 검증한 뒤 `normalizeWeights()`(`lib/calc.ts:152`)로 음수는 0으로 바꾸고 합 1로 맞춥니다: `:67`
- 키가 없거나, 실패하거나, 스키마가 맞지 않으면 키워드 분석으로 대체합니다.

### 4-2. 키워드 대체 분석 (`lib/weights.ts:16`)

```
weight_k ∝ 1 + 2 × (k 키워드 등장 수)       // :28
```

키워드가 하나도 없거나 글이 비어 있으면 균등(1/3)으로 둡니다.

### 4-3. 슬라이더 (`lib/calc.ts:130`, `:141`)

- 정수 %로 관리하고 합은 항상 100입니다. `toPercents`는 money와 time을 반올림하고 body에 나머지를 줍니다.
- `rebalance`: 바꾼 값을 [5, 90]으로 자른 뒤, 남은 몫을 나머지 둘에 기존 비율대로 나눕니다. 각각 최소 5%입니다.

## 5. 검증용 예시

공통 입력: 편도 85분, 환승 2회, 배차 0분(질문 삭제), 왕복 교통비 4,500원, 주 4일, 시급 10,320원, 월세 55만, 관리비 7만, 생활비 15만, 초기 비용 80만, 보증금 1,000만(3.5%)

> 월 등교일을 × 4.3으로, 초기 비용 기본값을 80만으로 바꾸면서 프로토타입 화면 숫자(28.8점, 59.7만 원)와는 달라졌습니다.

| 중간값 | 값 |
| --- | --- |
| savedDailyMin | 170 + 0 − 20 = 150분 |
| D | 4 × 4.3 = 17.2일 |
| ΔH | 2.5 × 17.2 = 43시간 |
| G_time | 443,760 (44.4만) |
| f / G_body | 0.35 / 155,316 (15.5만) |
| initialMonthly | 33,333 |
| depositCost | 29,167 |
| savedFare | 77,400 |
| ΔC | 755,100 (75.5만) |

**① 리포트, 가중치 돈 0.40 / 시간 0.35 / 체력 0.25 (L = 20)**

| 출력 | 값 |
| --- | --- |
| E | 3 × (0.35·443,760 + 0.25·155,316) = 582,435 |
| K | 1.2 × 755,100 = 906,120 |
| 자취지수 | 39.1 → 다시 생각해 보기 |
| W | 485,362 |
| 1시간 가치 / 되사는 가격 | ≈ 11,287원 / 17,560원 |

**② 월세 상한, 가중치 돈 0.20 / 시간 0.45 / 체력 0.35, 안암동(도보 10분 → L = 20, F_L = 0)**

| 출력 | 값 |
| --- | --- |
| E | 3 × (0.45·443,760 + 0.35·155,316) = 762,158 |
| W | 762,158 / 0.6 = 1,270,263 (127.0만) |
| rentCap | 1,270,263 − 70,000 − 150,000 − 33,333 − 29,167 + 77,400 = 1,065,163 (106.5만) |

빠른 확인용 스크립트 (Node 22+는 TS를 바로 실행합니다):

```ts
import { compute } from "./lib/calc.ts";
const c = { oneWayMin: 85, transfers: 2, headwayMin: 0, roundTripFare: 4500, daysPerWeek: 4, hourlyWage: 10320 };
const cost = { rent: 550000, mgmt: 70000, living: 150000, initialTotal: 800000, deposit: 10000000, annualRate: 0.035 };
compute(c, cost, { money: .4, time: .35, body: .25 }).index;            // 39.13
compute(c, cost, { money: .2, time: .45, body: .35 }, 20, 0).rentCap;   // 1,065,163
```

## 6. 기획서 초안과 다른 점

월 등교일은 기획서와 같은 `주당 등교일 × 4.3`입니다. 그래도 기획서의 예시 계산(균등 가중치 51.3점 등)은 아래 차이 때문에 이 코드로는 재현되지 않습니다.

| 항목 | 기획서 초안 | 구현 | 이유 |
| --- | --- | --- | --- |
| 통학 시간 | 왕복 시간 | `2·편도 + 배차 간격`(배차 간격은 현재 0 고정) | 프로토타입의 "여유 시간 포함". 지금은 기획서와 같음 |
| 피로 계수 f | `0.2 + 0.1·n` (≤ 0.5) | `0.15 + 0.1·n` (≤ 0.5) | 프로토타입 화면이 환승 2회에서 0.35 |
| 초기 비용 | 없음 | `I / 24` 추가(기본 80만) | 프로토타입의 "초기 비용 (2년 분할)" |
| 자취 지역 교통비 | 없음 | 버스·지하철 지역이면 `F_L = 3,000` 차감 | 걸어갈 수 없는 지역 보정 |

## 7. 알려진 한계 / 팀 확정 필요

- **피로 계수**: 환승 횟수만 씁니다. 혼잡 시간대나 도보 시간은 반영하지 않습니다.
- **생활비·초기 비용·이율**: 기본값에 근거 자료가 없습니다.
- **판정 기준**: 50 단일 기준입니다. 45~55 "애매함" 구간은 없습니다.
- **자취 쪽 통학 시간**: 배차 대기를 넣지 않아서 통학 쪽과 비대칭입니다.
- **`F_L`**: 3,000원 상수입니다. 실제 요금이나 환승 할인을 반영하지 않습니다.
- **통학 정보**: Google Routes API로 경로를 고르면 편도·환승·왕복 교통비가 채워지고, 사용자가 고칠 수 있습니다(`GOOGLE_MAPS_UI.md`). 광역버스·GTX 요금은 아직 반영하지 않습니다.
- **시세 데이터**: 6개 학교 × 3개 동의 예시 값입니다. 국토부 전월세 실거래가 가공 전입니다.
- **극단값**: ΔH = 0이고 ΔC > 0이면 E = 0이라 지수는 0입니다. `w_m`은 슬라이더 최소값 5% 덕분에 UI에서는 0이 되지 않습니다.
